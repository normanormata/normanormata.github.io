. The theme applies the sidebar, text size, reading face and colour theme only once gitbook.js, theme.js and the plugins — ~290KB of script at the end of — have loaded and run. Until then a first visit rendered with no sidebar and in the theme's Helvetica, then jumped: the sidebar opened, the text moved 150px right and changed face, and a reader on Night, or on a dark system, saw a white page first. The logic mirrors what runs later, so the classes set here are the ones those scripts will set, and nothing flips back: - gitbook-plugin-fontsettings/fontsettings.js stores {size, family, theme} under ":fontState" (gitbook.storage has an empty base key), defaulting to the fontsettings block in _includes/metadata.json.tpl: size 2, serif (0), white (0). - theme.js opens the sidebar above 600px unless ":sidebar" is false. - followSystemTheme() in assets/gitbook/custom.js matches the system colour scheme while nothing is stored or "theme-follows-system" is "on". When that means a change, the state is written here first, so fontsettings.js starts from the same theme instead of restoring the old one over it. The layouts write the default size and face into the markup (class="book font-size-2 font-family-0"), so a reader without JavaScript gets the serif too; this replaces them when something else is stored.
